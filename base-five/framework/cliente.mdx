Funções do lado **cliente** (manipulação local do ped, câmera, veículos, objetos). Estão em `resources/vrp/client/*.lua`, na tabela `tvRP`, exposta via Tunnel.

Como chamar a partir do **servidor** (o primeiro argumento é sempre o `source` de destino):

```lua
local vRPC = Tunnel.getInterface("vRP")    -- em muitos recursos chamado vRPclient
vRPC.SetHealth(source, 200)                -- espera retorno
vRPC._SetHealth(source, 200)               -- fire-and-forget (sem retorno)
```

<Note>
  As funções abaixo NÃO recebem `source` como parâmetro próprio, agem sobre o player local. O `source` só aparece porque o Tunnel o consome como destino quando a chamada parte do servidor.
</Note>

## Handlers `tvRP` que vivem no servidor

Chamáveis pelo cliente via `vRPS`. Estão na tabela `tvRP` do **servidor** (`modules/player.lua` e `inventory.lua`), invocados pelo cliente via `vRPS = Tunnel.getInterface("vRP")`:

| Função | Descrição |
| --- | --- |
| `tvRP.CreateModels(Model,x,y,z,Type)` | Cria um ped no servidor; retorna o NetworkId. |
| `tvRP.CreateObject(Model,x,y,z,Weapon,Component)` | Cria um objeto rastreado pelo Passport; retorna o NetworkId. |
| `tvRP.Barbershop(Barbershop)` | Aplica os dados de aparência ao ped do chamador. |
| `tvRP.invUpdate(Slot,Target,Amount)` | Move/mescla itens entre slots. |
| `tvRP.DowngradeThirst()` / `tvRP.DowngradeHunger()` | Reduzem 1 ponto de sede/fome do chamador. |

## Observações

<Info>
  - Funções utilitárias globais (não `tvRP`) vêm de `lib/utils.lua`: `parseInt`, `splitString`, `SplitOne`, `GenerateString`, `Base64`, `HexToRGB`, `async`, `module`. São globais, não métodos de `vRP`/`tvRP`.
  - Estados de player (`LocalPlayer.state.*` / `Player(source).state.*`), como `Passport`, `Active`, `Route`, `Banned`, `Handcuff`, sincronizam condição entre cliente e servidor.
</Info>
