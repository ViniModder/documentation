## Apresentação

O **Combo Late Game** é um sistema completo de partidas competitivas para servidores FiveM. Os jogadores criam salas, formam times, desafiam outras salas e votam no modo de jogo e mapa antes de iniciar a partida em formato melhor de N rounds com troca de lados opcional, placar ao vivo, kill feed e zona segura que fecha progressivamente.

### Funcionalidades Principais

#### Sistema de Salas
- Criação de salas com nome customizado
- Limite configurável de membros por sala (padrão: 10)
- Sistema de dono (owner) da sala com permissões de kick
- Entrada em salas existentes
- Saída automática ao desconectar

#### Sistema de Desafios
- Líderes de sala podem desafiar outras salas
- Sistema de convites com aceitação/rejeição
- Previne desafios para a própria sala
- Bloqueio de solicitações pendentes

#### Votação
- Votação em duas fases: Modo de jogo → Mapa
- Chat de votação entre participantes
- Sistema de chat com delay anti-spam
- Tempo configurável por convar para cada fase
- Resolução por maioria ou pluralidade

#### Modos de Jogo
- **Pistols**: Pistolas diversas
- **Rifles**: Rifles de assalto
- **Submachine**: Submetralhadoras
- **MixedGuns**: Combinação progressiva de armas
- Configuração de armas por round
- Weapon pool configurável

#### Mapas Incluídos
- Mirage Exclusive
- Dust 1.6
- Dust Go
- ItalyV1
- ClockTower
- Sistema de Safezone que fecha progressivamente
- Configuração de dano por segundo fora da zona
- Spawn points configuráveis por time
- Distância de spawn configurável

#### Sistema de Partidas
- Melhor de N rounds (configurável, padrão: 10)
- Troca de lados opcional por round
- Proteção de spawn configurável
- Sistema de death/respawn
- Round delay configurável
- Placar ao vivo (HOME key)
- Kill feed com nomes dos jogadores

#### Espectação
- Espectar partidas em andamento
- Sistema de target automático
- Comando para sair do modo espectador
- Acompanhamento de estatísticas em tempo real

#### Integração
- Suporte nativo para vRP/vRP 2.0
- Adaptável para QBCore, ESX e outros frameworks
- Sistema de passport/user_id
- Verificação de permissões
- Sistema de nomes personalizados
- Verificação de nomes reservados
- Webhook de vencedor (configurável)
- Salvamento/restauração de estado do jogador

#### Routing Buckets
- Uso de routing buckets isolados por partida
- Verificação de capacidade de entrada
- Salvamento de coordenadas de retorno
- Restauração automática ao sair

## Compatibilidade

### Frameworks Suportados

- ✅ **vRP** (suporte nativo)
- ✅ **vRP 2.0** (suporte nativo)
- 🔄 **QBCore** (requer adaptação - veja [/instalacao](/combo-lategame/instalacao))

- FiveM Server com OneSync habilitado
- Server Version 2843 ou superior
- Lua 5.4+

## Fluxo de Uso

### 1. Criação de Sala

```
Jogador abre painel (/lategame ou marker)
  ↓
Cria sala com nome
  ↓
Outros jogadores entram na sala
  ↓
Sala pronta para desafios
```

### 2. Sistema de Desafios

```
Líder da Sala A desafia Sala B
  ↓
Líder da Sala B recebe convite
  ↓
Líder da Sala B aceita desafio
  ↓
Inicia votação
```

### 3. Votação

```
Fase 1: Votação de Modo
  ↓
Todos votam em modo de jogo
  ↓
Modo mais votado é selecionado
  ↓
Fase 2: Votação de Mapa
  ↓
Todos votam em mapa
  ↓
Mapa mais votado é selecionado
  ↓
Partida inicia
```

### 4. Partida

```
Jogadores são teleportados
  ↓
Armas são distribuídas
  ↓
Rounds iniciam
  ↓
Time vence round → ponto
  ↓
Primeiro time a atingir X pontos vence
  ↓
Jogadores são restaurados
```

## Comandos

### Client

| Comando | Descrição |
|---------|-----------|
| `/lategame` | Abre o painel do Late Game |
| `/aceitarlg` | Aceita desafio pendente |
| `HOME` | Abre/fecha o scoreboard (configurável) |
| `F7` | Sai do modo espectador (configurável) |

### Server

| Comando | Descrição |
|---------|-----------|
| `combo_lategame_reset_voting` | Reseta votações (console only) |

## Convars

| Convar | Padrão | Descrição |
|--------|--------|-----------|
| `combo_lategame_vote_mode_sec` | 120 | Tempo de votação de modo (segundos) |
| `combo_lategame_vote_map_sec` | 120 | Tempo de votação de mapa (segundos) |

## Troubleshooting

### Erro: "vrp/lib/utils.lua nao encontrado"

**Causa**: O resource vRP não está iniciado ou o nome está incorreto.

**Solução**:
1. Verifique se `ensure vrp` está no server.cfg antes de `ensure combo_lategame`
2. Verifique se o nome do resource é `vrp` ou `vRP` (maiúscula)
3. Se não usar vRP, adapte as funções de integração conforme [/instalacao](/combo-lategame/instalacao)

### Painel não abre

**Causa**: Markers não configurados ou comando não registrado.

**Solução**:
1. Adicione coordenadas em `globalConfig.Markers` em `config/config.lua`
2. Ou use o comando `/lategame`
3. Verifique se a UI está carregando corretamente (web/dist/index.html)

### Partidas não iniciam

**Causa**: Mapas ou modos não configurados corretamente.

**Solução**:
1. Verifique se `config.Maps` e `config.Modes` estão configurados
2. Verifique se as coordenadas de spawn estão corretas
3. Verifique se as imagens dos banners existem em `web/images/`
4. Verifique o console do servidor para erros

### Jogadores não são restaurados

**Causa**: Funções de save/restore não funcionando para o framework.

**Solução**:
1. Verifique `savePlayerInfos` e `setPlayerInfos` em `config/server/functions.lua`
2. Verifique se `DisableDimensionsVerify` está configurado corretamente
3. Teste as funções individualmente com prints/console

### Votação encerra prematuramente

**Causa**: Tempo de votação muito curto.

**Solução**:
1. Aumente os tempos das convars:
   ```cfg
   set combo_lategame_vote_mode_sec 180
   set combo_lategame_vote_map_sec 180
   ```

### Jogadores ficam presos após partida

**Causa**: Routing bucket não restaurado ou coordenadas inválidas.

**Solução**:
1. Verifique se `setPlayerRoutingBucket` está funcionando
2. Verifique se as coordenadas salvas são válidas
3. Aumente o delay em `setPlayerInfos` se necessário

### Safezone não causa dano

**Causa**: `DamagePerSecond` configurado como 0 ou lógica não implementada.

**Solução**:
1. Verifique se `DamagePerSecond` está > 0 na configuração do mapa
2. Implemente a lógica de dano se necessário (pode precisar de script adicional)
